# Contributing

Thank you for improving the starter. Begin with the detailed [contributor guide](docs/contributing.md), [component guidelines](docs/component-guidelines.md), and [architecture decisions](docs/decisions/README.md).

Open a structured issue before proposing a substantial component or public API. Keep pull requests focused, include a Changeset for user-visible work, and complete the repository's documented quality commands. Public properties, events, slots, parts, tokens, exports, and browser-support changes require compatibility reasoning and appropriate documentation.

Report vulnerabilities through [SECURITY.md](SECURITY.md), not a public issue.
